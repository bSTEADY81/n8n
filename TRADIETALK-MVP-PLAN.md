# TradieTalk: Audit and MVP Plan

Date: 10 September 2026
Codebase audited: `bSTEADY81/tradietalk` at commit `f0c3771` (main, 8 Nov 2025)
Also inspected: Vercel team "BJ's projects" deployment history for the tradietalk projects

---

## 1. The short version

1. **The voice agent you remember is not in this codebase.** It lived in an earlier repo (`bSTEADY81/Tradietalk`, July 2025, generated by Abacus AI) that used **Vapi** and was deployed at `tradietalk.vercel.app` in Vercel's **Washington DC region (iad1)**. That repo no longer exists on GitHub. The latency and robotic feel came from that stack: every turn went Australia → US → Vapi's default STT/LLM/TTS chain → back, with no barge-in and a default synthetic voice.
2. **The current repo has no voice agent at all.** It is a push-to-talk recorder: record → stop → upload the whole clip → Whisper → text in a textbox. There is no speech output, no conversation, and the "Generate Quote" button on the mobile component is a `TODO` that shows a toast. The golden path (speak → quote → PDF → email) is not wired end to end.
3. **The app typechecks and is structurally sound** (Next.js 14, Prisma, NextAuth, shadcn). It needs about a week of fix-up before it is a trustworthy base, then the conversational agent goes on top.
4. **Recommendation for the agent:** build it on **ElevenLabs Agents** (Conversational AI) with WebRTC, an Australian voice, and tool calls into our own API. Alternative: OpenAI Realtime API. Either gets to the ChatGPT-voice feel; neither is achievable with Whisper-on-a-file or a US-hosted Vapi default.

## 2. Why ChatGPT voice and ElevenLabs agents feel smooth, and why TradieTalk did not

| Property | ChatGPT voice / ElevenLabs agent | Old TradieTalk (Vapi, iad1) | Current TradieTalk |
|---|---|---|---|
| Transport | WebRTC, full duplex, streaming both ways | WebRTC via Vapi, but US-hosted | HTTP upload of a finished file |
| Time to first spoken word | 300 to 700 ms | 1.5 to 3 s | never speaks |
| Turn detection | Server-side VAD with semantic end-of-turn | Basic VAD, fixed silence timeout | User taps Stop |
| Interruptions (barge-in) | Yes, instantly cancels speech | Partial or off by default | n/a |
| Speech synthesis | Native speech-to-speech, or streaming TTS with sentence-level chunking | Default Vapi voice (often PlayHT/Azure) at default settings | none |
| Transcription | Streaming partials while you talk | Streaming | Whisper batch, 5 to 15 s for a 1 to 2 minute clip |
| Server location | Nearest edge | US East | Sydney (syd1) configured, but no deployments exist on that project |
| Filler behaviour | Starts speaking before the LLM has finished | Waits for full completion | n/a |

The physics: a round trip Brisbane → Virginia is about 200 ms each way before any model runs. Chain STT + LLM + TTS serially, wait for full completion at each stage, and you are at 2 to 3 seconds of dead air. That reads as "slow and robotic" even when the voice itself is fine.

### Latency budget for the new agent (target under 800 ms to first audio)

| Stage | Target | How |
|---|---|---|
| Mic → server | under 50 ms | WebRTC (Opus), not HTTP |
| End-of-turn detection | 200 to 400 ms | Provider VAD with semantic turn detection |
| STT final | under 150 ms | Streaming STT already caught up during speech |
| LLM first token | 200 to 400 ms | Small, fast model with cached system prompt |
| TTS first chunk | under 100 ms | Flash-class TTS, sentence-level streaming |
| Server → speaker | under 50 ms | WebRTC |

## 4. Voice agent architecture

### Options

| | A. OpenAI Realtime API | B. ElevenLabs Agents (recommended) | C. Self-assembled (LiveKit or Pipecat + Deepgram + Claude + ElevenLabs Flash) | D. Return to Vapi, reconfigured |
|---|---|---|---|---|
| Model | Native speech-to-speech | STT → any LLM → ElevenLabs TTS, tightly streamed | Anything | STT → LLM → TTS |
| Voice quality | Good, limited voice set | Best available, Australian voices, voice cloning | Best (same TTS) | Depends on config |
| Latency to first audio | ~500 ms | ~600 to 800 ms | ~600 to 900 ms | ~800 ms if pinned to ElevenLabs Flash + Deepgram |
| Barge-in and turn-taking | Built in | Built in | You tune it | Built in |
| Tool calling into our API | Yes | Yes (server tools and client tools) | Yes | Yes |
| Effort to ship | 3 to 5 days | 3 to 5 days | 2 to 3 weeks | 2 days |
| Cost per minute (approx.) | US$0.10 to 0.30 depending on audio in/out mix | US$0.08 to 0.10 | US$0.03 to 0.06 plus hosting | US$0.10 to 0.15 |
| Lock-in | High (single vendor model) | Medium (LLM is swappable) | Low | Medium |

**Pick B.** The voice is the product for tradies; ElevenLabs is the benchmark you named. Its agent platform handles VAD, interruptions, and streaming, exposes a WebRTC SDK for the browser, lets us bring our own LLM prompt, and calls webhooks on our Next.js API for the actual work. If we later want to drop cost, C reuses the same TTS.

Keep push-to-talk Whisper as a **fallback mode** for a screaming worksite or a dead spot: it is offline-tolerant, and the agent is not.

### How a conversation works

```
Tradie taps "Talk"
  → browser opens WebRTC session to ElevenLabs (signed URL from our /api/voice/session)
  → agent greets: "G'day Brad, what are we quoting?"
  → tradie describes the job, interrupts, corrects
  → agent calls our tools as it goes:
      lookup_client(name)            → existing client or "new client" prompt
      get_catalog_prices(query)      → the tradie's own rates, never invented
      upsert_quote_draft(items...)   → draft persists server-side after every tool call
  → live transcript and a growing line-item card render on the phone
  → agent reads back the total once and asks to confirm
  → "Send it" → tool finalise_quote → PDF → Resend email → status SENT
```

Rules for the agent prompt:

- Never invent a price. If no catalog match and no spoken price, ask.
- Confirm quantities and units out loud once, then stop confirming.
- Speak in short sentences. No lists read aloud.
- Australian English, GST always stated as "inc GST" or "plus GST".

### Where the code changes

| Piece | New or changed |
|---|---|
| `app/api/voice/session/route.ts` | Mints a signed ElevenLabs session URL for the logged-in user, injects user context (name, trade, GST status) as dynamic variables |
| `app/api/voice/tools/*` | Webhook endpoints the agent calls: `lookup-client`, `catalog-prices`, `upsert-draft`, `finalise-quote`. Each verifies the ElevenLabs signature and the user id embedded in the session |
| `components/voice-agent.tsx` | Replaces `voice-to-quote-mobile.tsx` as primary. Talk button, live transcript, line-item card, interrupt-safe, mic level meter |
| `lib/quote-draft.ts` | Draft state in Postgres (`QuoteDraft` model), keyed by session, so a dropped call does not lose work |
| `lib/pricing.ts` | Catalog search plus explicit "no match" result. No default rates |
| Fallback | Keep `/api/transcribe` but switch to `gpt-4o-mini-transcribe` and stream partials; remove mock fallback on failure |

### LLM choice for the agent brain and for structured extraction

Drop the Abacus proxy. Call the model vendor directly. For the agent brain a fast model matters more than a smart one; for the final structured quote extraction use a stronger model with a JSON schema and validate with `zod` before it touches the database.

## 5. MVP plan

MVP definition: a tradie on an iPhone or Android phone can sign up, set up their business, hold a natural voice conversation that produces a correct quote using their own prices, review and edit it, and email it as a PDF to a client. All from the phone, in under three minutes, with no fake data anywhere.

### Phase 0: Make the base trustworthy (2 days)

- [ ] Remove `.next/`, `dev.db`, logs, `.DS_Store`, `tsbuildinfo` from git. (R2)
- [ ] Fix `package.json`: align `eslint-config-next` with Next 14 (or upgrade to Next 15 and align everything), drop unused deps, drop `ie 11`. Make `npm ci` pass. (R1, R3, R4)
- [ ] Switch Prisma to Postgres. Create a Neon or Supabase database. Reset migrations. (D2)
- [ ] `quoteNumber` uniqueness becomes `@@unique([userId, quoteNumber])`; increment atomically inside a transaction. (D1, D3)
- [ ] One GST convention: store as a fraction (`0.10`) everywhere; migrate; fix docs. (D4)
- [ ] Every API route uses `getServerSession(authOptions)`; add a `requireUser()` helper. (A1)
- [ ] Register Google provider only when env vars exist. (A2)
- [ ] Add `middleware.ts` protecting `/dashboard`, `/quotes`, `/clients`, `/settings`. (A3)
- [ ] Credentials signup creates `BusinessSettings` in the same transaction. (D5)
- [ ] Rotate any key that was ever in the committed `.env`. (A6)
- [ ] Collapse the 37 root docs into `README.md`, `CLAUDE.md`, and `docs/`. Delete stale Vercel projects. (R5, R8)
- [ ] Add GitHub Actions: install, typecheck, lint, build on every push.

### Phase 1: Wire the golden path without the agent (3 days)

- [ ] `GET/PUT/DELETE /api/quotes/[id]`, `PUT/DELETE /api/clients/[id]`, `PUT /api/settings`. (D6, D7)
- [ ] Editable Settings page: business name, ABN, address, phone, GST registered, quote prefix, default terms. (D7)
- [ ] Quote review screen: edit line items, quantities, rates; pick or create client inline; see subtotal, GST, total live.
- [ ] Mobile voice component: transcribe → generate → review → save actually works. Remove the legacy Web Speech component. (V1)
- [ ] Switch transcription to `gpt-4o-mini-transcribe`; delete the mock fallback on failure; return a real error instead. (V3, V4)
- [ ] Structured quote extraction: direct vendor call, JSON schema, `zod` validation, catalog-grounded prices, "needs price" flag instead of invented numbers. (V5, V6)
- [ ] Send flow: confirm dialog with editable subject and message, then PDF via Resend. Show sent status.
- [ ] Validate request bodies with `zod` on every `POST`/`PUT`. (D10)

### Phase 2: The conversational agent (5 days)

- [ ] ElevenLabs agent configured: Australian voice, Flash TTS, our system prompt, dynamic variables for user context.
- [ ] `/api/voice/session` and the four tool webhooks with signature verification.
- [ ] `QuoteDraft` model and `lib/quote-draft.ts`.
- [ ] `components/voice-agent.tsx`: WebRTC session, talk button, live transcript, line-item card updating as tools fire, mic level meter, interrupt handling, reconnect on drop.
- [ ] Push-to-talk fallback toggle in the same screen.
- [ ] Measure on a real phone over 4G: time to first agent word, turn latency, interruption responsiveness. Targets in section 2.
- [ ] Tune VAD sensitivity and end-of-turn timing for outdoor noise.

### Phase 3: Beta hardening (4 days)

- [ ] Rate limiting with Upstash on auth and every endpoint that costs money. (A4)
- [ ] Sentry for server and client. Make `/api/health` dynamic so it really checks the database, then wire it to UptimeRobot.
- [ ] Service worker for shell caching and offline recording queue; real screenshot in the manifest. (M1)
- [ ] Either implement `dark:` styles or pin the theme to light. (M2)
- [ ] Templates and price catalog UI (import from CSV, edit rates). (D8)
- [ ] Real ABR lookup for ABN, or remove the fake business name. (D9)
- [ ] Playwright smoke test of the golden path; unit tests for GST maths and quote numbering.
- [ ] Beta with three tradies on their own phones; the checklist in `MOBILE_BETA_TESTING_CHECKLIST.md` already exists and is usable.

### Phase 4: Launch (2 days)

- [ ] Domain, `NEXTAUTH_URL`, Resend domain verification, production env vars on the `tradietalk-app` Vercel project (region `syd1`).
- [ ] Prisma `migrate deploy` in the build step.
- [ ] Privacy policy and terms (voice recordings are personal information under the Privacy Act).
- [ ] Cost monitoring: per-user minutes of agent time, alert thresholds.

Total: roughly 16 working days for one developer, with the agent (Phase 2) being the part that most benefits from a spike first to validate voice and latency before the surrounding UI is polished.
